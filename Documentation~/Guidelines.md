# Integration and contribution guidelines

| Concern | Rule |
| --- | --- |
| Application contracts | Define small read-only interfaces on Ghost roots or module components for query consumers. Reusable `EntityModule<TData>` components accept source-independent data. Consumers use `IGhost.TryGet<T>` or `GetRequired<T>()`; keep one root provider per contract. |
| Presence setup | Configure modules on the Ghost prefab or through RequireComponent. Register `Realm.RegisterPresenceInitializer<TGhost>` to bind their readers before detectors attach. Prefab configurators implement `IRealmConfigurator`. Initializers reconnect retained Ghosts after disappearance or handover. Detectors only announce membership with Detect and Disappear; module readers own data updates. An unassigned blueprint keeps the root viewless. |
| Coordinates | Define units and axes in application contracts. Ordinary sample positions are anchor-local. For large or moving-reference worlds, preserve global doubles in `Double3`, normalize SDK inputs in initializer-bound readers, and let modules apply the shared Cartesian values to root `Spatial` components. Use a prefab-configured `RealmSetup` reference frame or a code-configured `Realm.ReferenceFrame`. Projection assigns world poses and handles Anchor parent offsets. See [Spatial](Spatial.md). |
| Spatial ownership | Keep the desired Unity reference near the scene origin and set an appropriate presentation range. Position and orientation are independent channels; articulation can use another application module. Use one root transform writer: remove existing position behaviors from spatial roots, and integrate dynamic physics explicitly. Network scenery should share the same projection; a local cockpit may remain fixed. |
| Ownership | Emas owns the lifetime of Presences, anchors, Ghost roots, installed modules, views and availability. Applications own SDK clients, module types and prefab assets. Each `RealmSetup` owns an isolated realm, while each `AnchorSetup` creates one detector through its colocated `IDetectorProvider`. The realm owns one blueprint mapping per Kind, shared by all its anchors; re-registration refreshes requested views throughout that realm while retaining roots. Detector cleanup unsubscribes but does not dispose a shared client. Dispose query subscriptions and clear retained membership when their consumer stops. |
| Threading and payloads | Call Emas only on Unity's main thread, including detector report/remove callbacks and `Dispatch`. The application owns SDK threading and delivers events on that thread. Copy mutable or reused SDK payloads before queuing reports for a later realm update. Capture a dispatcher in `OnStart`, close SDK callbacks over it, and unsubscribe in `OnStop`. The dispatcher rejects calls from an old attachment. Order initial data with live events and undo partial subscriptions if startup throws. |
| Failure and recovery | Read `LastErrorContext` and `LastError` on the detector; **Window > Emas** inspects all live Realms through a Realm selector. Set `detector.Name` to distinguish feeds. Detector failure removes its population. Fix the cause, then use `anchor.RestartDetector(detector)` or `ReplaceDetector` to populate it again. Successful restarts or replacements reuse compatible roots and Presences reported during startup handover and remove unreported roots afterward. There is no automatic retry. |
| Disappearance and silent feeds | An explicit disappearance makes a Presence unavailable immediately. Set `detector.DisappearanceGracePeriod` before attachment to retain its inactive root and stable handle for a possible return; zero, the default, removes immediately. `InactivityTimeout` detects feeds that silently stop reporting and follows the same disappearance path. Set a positive timeout longer than the normal publication interval; leave it null for change-only feeds. Every successful report records activity, while direct integrations updating a cached Ghost can call `MarkPublished`. |
| Presentation failures | A view creation or refresh failure removes that view and logs its Ghost and prefab context; tracking stays active. Fix the cause and call `Manifest`, or change the manifestation blueprint, variant or detail to retry. Unchanged reports do not retry automatically. |
| Extension choice | Implement an application-specific `PresenceDetector` subclass. Use `OnStart` for existing arrivals or membership subscriptions, `OnUpdate` for presence polling if needed, and `OnStop` for cleanup. Call `Detect` for identity and metadata; use `Disappear` for missing identities. Ghost modules read their initializer-bound values each realm update. Keep SDK types in the application mapping and out of reusable modules and consumers. |
| Contributions | Use C# 8, Allman braces, XML docs and Unity metadata. Keep runtime independent of editor, sample and SDK assemblies. Cover public behavior with Unity tests, update the changelog, and synchronize shipped samples with `Tests/Unity~/Assets/Samples`. Change version or assembly names only as part of an explicit release decision. |
