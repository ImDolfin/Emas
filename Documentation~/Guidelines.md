# Integration and contribution guidelines

| Concern | Rule |
| --- | --- |
| Application contracts | Define small read-only interfaces in your application. Implement them on `Ghost` or other root components; keep setters on concrete ghosts for source mapping. Consumers use `IGhost.TryGet<T>` for optional contracts or `GetRequired<T>()` for required ones. One root provider per contract. |
| Coordinates | Define units and axes in the application contract. Ordinary sample positions are anchor-local. For large or moving-reference worlds, preserve global doubles in `Double3`, normalize all sources to shared Cartesian coordinates and use root `Spatial` components with a prefab-configured `RealmSetup` reference frame or a code-configured `Realm.ReferenceFrame`. Projection assigns world poses and handles Anchor parent offsets. See [Spatial](Spatial.md). |
| Spatial ownership | Keep the desired Unity reference near the scene origin and set an appropriate presentation range. Position and orientation are independent channels; articulation remains application-owned. Use one root transform writer: remove existing position behaviors from spatial ghosts, and integrate dynamic physics explicitly. Network scenery should share the same projection; a local cockpit may remain fixed. |
| Ownership | Emas owns anchors, ghost roots, views and availability. Applications own SDK clients and prefab assets. Each `RealmSetup` owns its isolated realm, while each `AnchorSetup` creates one source through its colocated `ISourceProvider`. Anchor manifestation blueprints override realm defaults and leave with the anchor; re-registration refreshes requested views while retaining roots. Source cleanup unsubscribes but does not dispose a shared client. Dispose query subscriptions and clear retained membership when their consumer stops; disposal does not invoke departure callbacks. |
| Threading and payloads | Call Emas only on Unity's main thread, including publish/remove and `Dispatch`. The application owns SDK threading and delivers events on that thread; copy mutable/reused SDK payloads before publishing. Order initial data with live events and undo partial subscriptions if startup throws. Custom sources must invalidate old callbacks before reattachment. |
| Failure and recovery | Read `LastErrorContext` and `LastError`, or **Window > Emas**. Set `source.Name` to distinguish feeds. Source failure removes its ghosts. Fix the cause, then use `anchor.RestartSource(source)` or `ReplaceSource` to populate new roots. Successful restarts/replacements reuse compatible roots republished during startup handover and remove unreported roots afterward. There is no automatic source retry. |
| Silent entities | Set a positive `source.InactivityTimeout` before attachment when a feed can silently stop reporting an entity. Allow for its normal publication interval. Any partial publication resets activity; custom sources writing cached ghosts call `MarkPublished`. Expired roots and views are removed. Null, the default, disables expiry. |
| Presentation failures | A failure caught during view creation/refresh removes that view and logs its ghost/prefab context; tracking stays active. Fix the cause and call `Manifest`, or change the manifestation blueprint, variant or detail to retry. Unchanged updates do not retry automatically. |
| Extension choice | Start with fluent polling or callback builders. Subclass `PresenceSource` for custom lifecycle requirements; do not expose SDK types to view consumers. Keep callbacks short. |
| Contributions | Use C# 8, Allman braces, XML docs and Unity metadata. Keep runtime independent of editor/sample/SDK assemblies. Cover public behavior with Unity tests, update the changelog, and synchronize shipped samples with `Tests/Unity~/Assets/Samples`. Change version or assembly names only as part of an explicit release decision. |
